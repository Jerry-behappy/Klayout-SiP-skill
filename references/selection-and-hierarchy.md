# 目标选择与层级处理

## Marker layer 选择

- 先确认 marker 所在 cell、layer/datatype、图形数量和 bbox。
- 对矩形框或矩形边框，可用 marker bbox 作为选择区域；对任意多边形，使用真实 Region/点包含关系，不用 bbox 代替。
- 常用实例选择规则是“变换后 bbox 中心位于 marker 内”。若用户要求完全圈入或相交，分别使用完全包含或相交规则并在报告中说明。
- marker 自身默认保持不变；只有用户明确要求时才删除或移动。

## 层级与变换

- `top.each_inst()` 只覆盖直接子实例。目标可能位于更深层级、阵列元素中，或已经扁平化为 shape。
- 递归遍历时按 `global_trans = parent_trans * local_trans` 合成变换，并记录父 cell 和实例路径。
- PCell 内部生成的子 cell 不是独立设计对象。除非任务明确要求，不进入 PCell 内部逐 shape 修改。
- 对阵列保存 `na`、`nb`、`a`、`b`；替换 cell 时不要把阵列展开成多个普通实例。
- 旋转实例时区分“绕实例原点旋转”和“绕选择中心旋转”。通常 PCell 单体编辑保持位移，只改变角度。

## 为后续修改组织共享层级

- 绘制或重构重复电路时，先识别功能分组与最小重复单元，再确定 cell 层级；例如整机/阵列 → 分组 → 单路 → 各级器件及局部连接。先完成和核验一个重复单元，再通过同一 cell 的旋转、镜像或阵列实例逐级组合，使一次修改同步作用到全部相同位置。
- 相同几何和参数复用同一 cell；需要不同长度或局部例外时，使用明确的级/变体 cell。器件和它的局部接线可放入同一级容器，跨单元的公共路由归属于最近的公共父 cell；不为方便选取而把整网扁平化或复制成大量独立图形。
- 参考既有版图时，从实际实例路径、共享关系、端口和变换重建层级，不能只仿造截图中的 cell 名。已展开版图先在不改变几何的前提下恢复共享层级，再修改最小重复单元；实例恢复属性中的坐标按所属 cell 的局部坐标维护。
- 修改共享 cell 前确认展开后的影响范围；仅改变少数位置时先隔离该分支。用户要求不改的金属或器件应保留位置、几何及电气连接，不能借层级重组顺带移动。
- 单元内部检查通过后，还须在完整父级环境检查新增器件及接线是否与相邻单元、返回母线或其他公共路由冲突；需要避让时在合适父 cell 中修改公共接线，保留固定端点并复查接缝。用共享 cell 数和展开后的实例数分别验收，不能仅凭树状名称宣称实现复用。

## 重复项与共享 cell

- 多个实例可以具有相同 cell、文字、变换甚至完全重叠。验收时使用 `collections.Counter` 表示多重集合。
- 不用 `{text: instance}` 或 `{transform: instance}` 作为唯一映射，除非已证明键唯一。
- 修改共享静态 cell 几何会影响所有引用；若只改一个位置，先创建独立 cell 或改为实例级 PCell variant。

## 识别优先级

按以下顺序识别目标：

1. 有效 library/PCell 身份和参数。
2. 明确的 cell 名与父级路径。
3. 端口、标签、实例变换和 bbox。
4. 扁平化后的重复几何特征，例如稳定的主多边形尺寸和局部层组合。
5. 截图只用于确认视觉顺序或意图，不作为唯一几何依据。

使用几何模式时必须同时验证数量、坐标分布和已知锚点。不要把某次项目中的 bbox 尺寸写死为跨项目规则。

## 修改前快照

- 先把目标实例保存为列表，再开始修改，避免迭代过程中 variant 变化导致漏项。
- 为目标记录原参数和变换；为非目标记录实例多重集合及任务需要的几何。不默认生成哈希，具体比较方法按 [verification.md](verification.md) 选择。
- 已知用户在 GUI 保存或源文件版本发生变化时，在覆盖前重新核对输入；若输入已变化，重新读取并调整候选。只有确需完整性或并发修改证据时才增加哈希比较。
